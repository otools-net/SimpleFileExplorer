# Visual checks

Scripts that look at the real page in headless Edge (driver: `../docs-screenshots/cdp.mjs`), for layout bugs unit
tests can't see. Each needs a docs-screenshots run first (`node agents/tools/docs-screenshots/run.mjs ...`): it reuses
its build and seeded data in `<tmp>/sfe-docs` and starts its own app on another port. After a client change, rebuild
that copy first: `dotnet build src/Sfe.Api --artifacts-path <tmp>/sfe-docs/build` (run it twice if the first fails on
a missing `chunk-….js`).

| Script | Checks |
|---|---|
| `server-lost.mjs [<screenshot>]` | The ⋮ button's warning while the server doesn't answer: the page open, the app stopped (no warning for the first seconds, then the yellow ! and the menu line), started again (gone); saves the button and open menu (default `<tmp>/sfe-server-lost.png`; `docs/images/main-menu-server-lost.png` for the user docs) |
| `two-instances.mjs` | Two instances (copies of the docs-screenshots data, own keys) on :5097 and :5098 in one browser: signing in or out on one leaves the other signed in, the cookie has its port in its name, a session under the old shared name `sfe.session` still works and is renamed; `ok`/`FAIL` per check (exit code 1 on a failure) |
| `context-menus.mjs [<out prefix>]` | Real right clicks (CDP) on a file, a folder, a breadcrumb and the background, the ContextMenu key and Shift+F10 (the browser's echo swallowed), Shift and a text field keeping the browser's menu, Open in new tab opening a tab, the sheet at 390 px; prints `ok`/`FAIL` per check (exit code 1 on a failure), saves `<prefix>-file.png`, `-background.png`, `-viewer.png`, `-phone.png`. Also the viewer (picture, video and its Speed submenu), a tag chip, the main menu's links, the administration page, and no menu in a sheet or the viewer's bar while a reader keeps its own; every row of the context menu plan's map: a multi-selection, folder nav, quick links, a search result's folder, search history, the picture editor's canvas, the /player page, Duplicates, the trash (a file made and purged for it), the folder picker, and phone sheets (file, folder link, viewer). A tab it opens is closed again: a page left in a background tab isn't laid out (stale hit-testing) |
| `phone-sheets.mjs <out prefix>` | 390 px, classic scrollbars, list view: the item menu and a dialog sheet span the whole width (left 0, right 390), the rows keep their width and the scroll position stays; prints the numbers and saves `<prefix>-menu.png`, `<prefix>-dialog.png` |
| `overflow.mjs <out prefix> [scene...]` | Rows of buttons at the target sizes of the overflow menus epic (360×800, 390×844, 414×896, 800×360, 1280×800): each scene's rows (`.player-row`…) on one line, inside themselves and the screen, the page no wider than it; prints `ok`/`FAIL` with what left the row and the "⋯" menu's entries (exit code 1 on a failure), saves `<prefix>-<scene>-<size>.png` and `-menu.png`. Scenes: `viewer-video`, `viewer-fullscreen` (a real click on Fullscreen: the menu above the fullscreen player), `player-page`; more come with the epic's audit step |
| `narrow-audit.mjs <out prefix> [scene...]` | Every screen at the phone sizes (360×800, 390×844, 414×896, 800×360; `- list` lists the ~30 scenes: listing views, menus, dialogs, each viewer, the editors, the player and view pages, administration pages): reports elements off the screen, buttons cut off by a box that doesn't scroll, rows of 3+ buttons on several lines, the page wider than the screen; behind a modal dialog only the dialog counts; a summary per scene at the end; screenshots `<prefix>-<scene>-<size>.png`. All scenes take ~12 minutes: run it in the background |
