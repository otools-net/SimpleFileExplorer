# client-generation

`generate.mjs` makes the raw layer of the C# client library, `src/Sfe.Client/Generated/` (`SfeRawClient`, namespace
`Otools.Net.Sfe.Client.Generated`), from the committed v1 document `tests/samples/openapi/v1.json` with Kiota
(the local tool of `dotnet-tools.json`, pinned). Note: `agents/docs/features/client-library.md`.

```sh
node agents/tools/client-generation/generate.mjs             # rewrites src/Sfe.Client/Generated
node agents/tools/client-generation/generate.mjs --check     # exit 1, with the files, when it would change
```

- Run it whenever `tests/samples/openapi/v1.json` changes (`OpenApiBaselineTests` writes it), in the same commit:
  `GenerationTests.RegeneratingTheClientChangesNothing` (`tests/Sfe.Client.Tests`) runs `--check`.
- Kiota generates into a temporary folder; the script drops `kiota-lock.json` (it holds the document's path relative
  to that folder) and writes the files with LF (Kiota writes CRLF on Windows), so the output is the same everywhere.
- The output is left as written: excluded from CSharpier (`.csharpierignore`) and from
  `agents/tools/readability/measure.mjs`; its files start with `// <auto-generated/>`, which analyzers skip.
- Only Kiota's JSON serializer is registered (`--serializer`/`--deserializer`): the document has JSON bodies only, and
  the package then needs three Kiota packages instead of the six of the bundle. A route with a text, form or binary
  body added to the document needs the matching option and package.
- Kiota warns, and keeps the lowest success status's schema, for routes whose statuses answer different schemas
  (`files/explore`, `files/explore/search`, `files/explore/unlock`: 200 and 202): the facade reads those itself.
- The script runs `dotnet tool restore` first (quick once restored), then Kiota offline (`KIOTA_OFFLINE_ENABLED`, no
  update check or hints): the document is a local file.
